React/Next

wat is React?

  • React lijkt het grootste framework te zijn
  • het is zwaarder dan frameworks waar ik bekend mee ben bijv. (svelte)
  • grote learningcurve (moeilijk)
  • veel libraries
  • werkt goed op mobile
  • goed voor componenten

React

    pro's

  • Grootste ecosysteem en community
  • Enorme vraag op de arbeidsmarkt
  • Herbruikbare componenten
  • Veel bibliotheken voor routing, state en formulieren
  • React Native voor mobiele apps
  • Goede tooling en documentatie

    con's

  • Is een bibliotheek, dus je moet zelf veel keuzes maken (routing, state, enz.)
  • Zwaarder dan Svelte of Solid
  • Hooks hebben een leercurve en valkuilen
  • Best practices veranderen regelmatig
  • Veel boilerplate bij complexe state
  • Extra tooling nodig voor SSR en SEO (meestal Next.js)

11ty (Eleventy)

    pro's

  • Stuurt standaard geen onnodige client-side JavaScript naar de browser
  • Ondersteunt veel templatetalen (Liquid, Nunjucks, Markdown, Handlebars, enz.)
  • Zeer snelle builds
  • Flexibel, legt geen vaste mapstructuur op
  • Eenvoudig te leren met weinig configuratie
  • Goed voor blogs, docs en portfolio's, met veel starters en plugins

    con's

  • Niet bedoeld voor zeer interactieve apps
  • Geen ingebouwd componentenmodel zoals React of Vue
  • Kleinere community dan Next.js of Astro
  • Weinig ingebouwde functies (zoals beeldoptimalisatie, dat gaat via plugins)
  • Veel dingen moet je zelf inrichten door het gebrek aan vaste conventies
  • Geen ingebouwde client-side routing of state-beheer

Vue.js

    pro's

  • Zachte leercurve
  • Uitstekende, duidelijke documentatie
  • Single-file components (HTML, JS en CSS bij elkaar)
  • Officiële tools voor routing en state (Vue Router, Pinia)
  • Goede performance
  • Gemakkelijk stap voor stap in te voeren in bestaande projecten

    con's

  • Kleinere arbeidsmarkt dan React
  • Kleiner ecosysteem
  • Minder grote bedrijven die het gebruiken
  • Options API en Composition API naast elkaar kunnen verwarren
  • TypeScript-ondersteuning was lange tijd minder sterk
  • Community is kleiner buiten Azië en Europa

Angular

    pro's

  • Complete oplossing met routing, formulieren, HTTP en testen ingebouwd
  • Sterke TypeScript-integratie
  • Duidelijke structuur voor grote teams
  • Dependency injection
  • Goede langetermijnondersteuning (door Google)
  • Krachtige CLI

    con's

  • Steile leercurve
  • Veel boilerplate
  • Zwaarder dan andere opties
  • Veel concepten (modules, services, RxJS)
  • Overkill voor kleine projecten
  • Grote updates kunnen veel migratiewerk vragen

Next.js

    pro's

  • Server-side rendering en statische generatie ingebouwd
  • Uitstekend voor SEO
  • File-based routing
  • API-routes en full-stack mogelijkheden
  • Grote community
  • Goede integratie met Vercel

    con's

  • Gebonden aan React
  • Complex door de App Router en Server Components
  • Veel veranderingen tussen versies
  • Self-hosten is lastiger dan op Vercel
  • Soms zwaar voor simpele sites
  • Risico op vendor lock-in

Astro

    pro's

  • Stuurt standaard bijna geen JavaScript naar de browser
  • Zeer snelle contentsites
  • Werkt met React, Vue, Svelte en meer in één project
  • Uitstekend voor blogs, docs en marketingsites
  • Goede Markdown/MDX-ondersteuning
  • Eenvoudig te leren

    con's

  • Minder geschikt voor zeer interactieve apps
  • Jonger ecosysteem
  • Meerdere frameworks mixen kan complex worden
  • Minder voorbeelden voor grote apps
  • Gedeelde state tussen islands is lastig
  • Kleinere community dan React of Vue

SolidJS

    pro's

  • Zeer hoge performance
  • Fijnmazige reactiviteit zonder virtual DOM
  • Syntax lijkt op React (JSX)
  • Kleine bundelgrootte
  • Goede TypeScript-ondersteuning
  • SolidStart voor full-stack

    con's

  • Klein ecosysteem
  • Weinig vacatures
  • Valkuilen als je React-gewoontes meeneemt (destructuring breekt reactiviteit)
  • Minder tutorials en leermateriaal
  • Minder bibliotheken van derden
  • Kleinere community

htmx

    pro's

  • Geen build-stap nodig
  • Zeer klein (ongeveer 14 KB)
  • Werkt met elke backend (Django, Laravel, Rails, enz.)
  • Interactiviteit via HTML-attributen
  • Makkelijk te leren
  • Past goed bij server-rendered apps

    con's

  • Niet geschikt voor zeer complexe client-side apps
  • Minder tooling en structuur
  • Geen componentenmodel zoals React of Vue
  • Grote projecten kunnen rommelig worden
  • Kleinere community
  • Veel logica verschuift naar de server

Alpine.js

    pro's

  • Super licht (ongeveer 15 KB)
  • Geen build-stap
  • Direct in HTML te gebruiken
  • Syntax lijkt op Vue
  • Goed voor kleine interacties (dropdowns, modals)
  • Werkt goed met Laravel, Liquid en andere templating

    con's

  • Niet bedoeld voor grote apps
  • Weinig structuur voor complexe state
  • Logica in HTML-attributen kan rommelig worden
  • Kleiner ecosysteem
  • Beperkte tooling en testen
  • Geen routing of SSR
